# Live Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new email reaches Mailbox within about a minute; EduSoft, IUPay, Blackboard and Outlook sync fully every 30 minutes; Mailbox and Overview update themselves; `sla-agent schedule` repairs the scheduled task.

**Architecture:** The scheduled task runs `sla-agent run` every minute. The site answers the check-in as today, but a full sync is due every 30 minutes and only full runs count for that (a new trigger `mail` marks mail-only runs). When no full sync is due, the agent asks an already-open Outlook for its newest email's time and, if it is newer than the last one uploaded, uploads just the Outlook part as a `mail` run. The status box reads full runs for its headline and the newest mail run for the Outlook line. Mailbox and Overview poll `/school/api/version` every 30 seconds and swap their `data-live` areas when a newer run finished.

**Tech Stack:** Python 3.12, pydantic, pywin32 (Windows only), pytest; Java 17, Spring Boot 4.1.1, Thymeleaf, Spring Data JPA, JUnit 5 + MockMvc, H2; plain JavaScript; headless Chrome for the browser check.

**Spec:** `docs/superpowers/specs/2026-10-01-live-sync-design.md` (approved 2026-10-01). Section numbers below (§3.3, §4.2 …) are that spec's.

**Starting point:** branch `outlook-mailbox` at the commit that adds this plan. Java: 627 tests pass; Python: every test passes.

## Global Constraints

- Full syncs every **30 minutes** (`Scheduling.FULL_SYNC_EVERY`); failed scheduled syncs still retry at most hourly; Sync now keeps its 5-minute gap; `RUN_TIMEOUT` stays 15 minutes.
- The trigger string for mail-only runs is exactly `mail` (`SchoolSyncRun.MAIL`); runs with it never count as full runs.
- The quick mail check uses only an Outlook that is **already open** (`GetActiveObject`, never `Dispatch`), reads only the newest email's arrival time, and gives up after **5 seconds** (`QUICK_LIMIT`). It never clicks or answers a prompt.
- A mail-only sync never logs in to EduSoft, Blackboard or IUPay and uploads exactly what a full sync's Outlook part uploads.
- Quiet minutes (nothing due, no new mail) write **nothing** to `agent.log` at INFO or above.
- The laptop warning appears after **1 hour** without a check-in.
- `/school/api/version` answers only the logged-in user's newest finished run id (any trigger), `0` when none.
- Live pages poll every **30 seconds** only while the tab is visible, never replace an area holding the focused element, and never show an error.
- The check-in answer keeps `"interval_hours": 12` (agents ignore it; old agents still parse it).
- Java 17, no new dependencies. Commands are for Git Bash from the repository root; Python is `.venv/Scripts/python.exe`. If a Spring test run fails with ClassNotFound for a class that exists in source, another process was compiling into `web/target`: rerun once.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- **Outlook opened after the page was built** (Mailbox showed "Outlook isn't connected yet"): the new page has areas the old one lacks, so live.js must reload the whole page rather than leave it stale (Task 4 pins the rule in the browser check).
- **A burst of mail-only runs** (20 after one full sync): the status box must still show the EduSoft/IUPay lines and a headline from the full sync (Task 3 pins it).
- **The session expired while a page stays open**: `/school/api/version` then redirects to the login page; live.js must ignore it quietly, not replace areas with a login form (Task 4's browser check pins it).
- **A mail-only sync while a full sync is running** (409 from the site): the agent must end quietly and try again next minute, not log a warning every minute (Task 5 pins it).
- **Outlook's newest item is a meeting request or unreadable**: the quick check must skip non-mail items and never crash the run (Task 5 pins it).

## Decided while planning (2026-10-01)

- Mailbox gets a third live area, `read` (the "Mail read from Outlook …" line), besides `status` and `mail`; the auto-Done setting stays outside every live area so its tick box is never replaced. The spec is updated.
- When the fresh page's set of live areas differs from the open page's (e.g. Outlook got connected), live.js reloads the whole page.
- `recentRuns` and `version` are default methods on `SchoolSyncRunRepository`, so `MailboxController` needs no new dependency.
- `Scheduling.decide` and `SyncStatus.describe` lose their `intervalHours` parameter (unused after this change); their tests are updated.

```js
/*
 * Mailbox and Overview update themselves (docs/superpowers/specs/2026-10-01-live-sync-design.md, 4.3). Every 30 s,
 * while the tab is visible, ask the site for the newest finished sync; when it is newer than this page, fetch the
 * page again and swap each [data-live] area, except one holding the focused element (it waits for the next round).
 * If the areas differ (e.g. Outlook got connected), the whole page reloads. Failures are silent: tried again later.
 */
document.addEventListener("DOMContentLoaded", function () {
  var main = document.querySelector("main[data-version]");
  if (!main) {
    return;
  }
  var EVERY_MS = 30000;
  var VIETNAM_OFFSET_MS = 7 * 60 * 60 * 1000;
  var note = document.createElement("p");
  note.className = "live-note";
  note.setAttribute("role", "status");
  note.hidden = true;
  document.body.appendChild(note);

  function names(root) {
    return Array.prototype.map.call(root.querySelectorAll("[data-live]"), function (area) {
      return area.dataset.live;
    }).sort().join(",");
  }
  function pad(n) {
    return (n < 10 ? "0" : "") + n;
  }
  function clock() {
    var vietnam = new Date(Date.now() + VIETNAM_OFFSET_MS);
    return pad(vietnam.getUTCHours()) + ":" + pad(vietnam.getUTCMinutes());
  }
  function focusedIn(area) {
    var focused = document.activeElement;
    return focused && focused !== document.body && area.contains(focused);
  }
  function refresh() {
    return fetch(location.pathname + location.search, { credentials: "same-origin" })
      .then(function (answer) {
        return answer.ok ? answer.text() : null;
      })
      .then(function (html) {
        var fresh = html && new DOMParser().parseFromString(html, "text/html");
        var freshMain = fresh && fresh.querySelector("main[data-version]");
        if (!freshMain) {
          return; // e.g. the login page after the session ended
        }
        if (names(fresh) !== names(document)) {
          location.reload();
          return;
        }
        var waiting = false;
        document.querySelectorAll("[data-live]").forEach(function (area) {
          if (focusedIn(area)) {
            waiting = true;
            return;
          }
          area.innerHTML = fresh.querySelector('[data-live="' + area.dataset.live + '"]').innerHTML;
        });
        if (!waiting) {
          main.dataset.version = freshMain.dataset.version;
        }
        note.textContent = "Updated " + clock();
        note.hidden = false;
        setTimeout(function () {
          note.hidden = true;
        }, 5000);
      });
  }
  function check() {
    if (document.visibilityState !== "visible") {
      return;
    }
    fetch("/school/api/version", { credentials: "same-origin", headers: { Accept: "application/json" } })
      .then(function (answer) {
        var json = answer.ok && (answer.headers.get("Content-Type") || "").indexOf("json") >= 0;
        return json ? answer.json() : null;
      })
      .then(function (answer) {
        if (answer && typeof answer.version === "number" && answer.version > Number(main.dataset.version)) {
          return refresh();
        }
      })
      .catch(function () {
        // tried again in 30 seconds
      });
  }
  setInterval(check, EVERY_MS);
});
```

```python
    """When the newest email in this account's Inbox arrived (aware UTC), from an Outlook that is already open;
    None when Outlook isn't open, the Inbox has no email, or Outlook doesn't answer within `limit`. Reads no text."""

    def work():
        app = running()
        if app is None:
            return None
        _, inbox = inbox_of(app, address)

        item = items.GetFirst()
        while item is not None:

        return None
```
